# 多用户体重管理设计

## 目标

将现有单用户体重网站扩展为无需登录的共享多用户看板。任何访问者都可以切换用户，并管理每个用户各自的减重计划、实际体重记录和每周里程碑。

首批用户为：

- Eason：承接当前线上全部计划、体重记录和里程碑，迁移过程中不得修改或丢失现有数据。
- Claire：默认计划为 2026-10-01 从 55.0 kg 开始，至 2026-12-31 达到 45.0 kg；初始不创建虚假的实际体重记录。

## 用户体验

### 用户切换

- 页面右上角增加用户选择器，显示当前用户姓名和下拉箭头。
- 下拉菜单列出所有用户，选择后整页切换到该用户的计划、图表、节点和日志。
- 切换期间显示读取状态；读取失败时保留原用户和原页面数据，不展示混合状态。
- 移动端与桌面端使用同一套用户选择和管理能力。

### 用户管理

用户选择器菜单底部提供三个管理入口：

- 添加用户：输入姓名后创建用户，并自动切换到该用户。普通新用户初始没有计划和实际体重记录，页面显示空状态并引导使用“编辑计划”完成首次计划设置。
- 重命名当前用户：修改显示名称，成功后当前页面立即更新。
- 删除当前用户：先展示会删除计划、体重记录和里程碑的风险说明，再由用户进行第二次确认。删除成功后自动切换到其他用户。

删除限制：

- 系统至少保留一个用户。
- 只剩最后一个用户时，删除入口禁用并说明原因。
- 删除操作不可恢复，但不得影响其他用户的数据。

### 名称规则

- 保存前移除用户名首尾空格。
- 用户名不能为空。
- 用户名必须唯一，按大小写不敏感方式比较；例如 `Eason` 与 `eason` 视为同名。
- 新增或重命名发生冲突时不写入数据库，并显示“该用户名已存在，请使用其他名称”。

## 数据模型

### 用户表

新增 `weight_profiles`：

- `id`：稳定的 UUID 主键。
- `name`：用户显示名称。
- `normalized_name`：用于大小写不敏感唯一约束的规范化名称。
- `created_at`、`updated_at`：审计时间。

数据库对 `normalized_name` 建立唯一约束，避免并发写入绕过前端校验。

### 现有表扩展

为下列表增加必填 `profile_id`，外键指向 `weight_profiles.id`：

- `weight_plan`
- `weight_entries`
- `weight_milestones`

现有的单例或日期唯一约束调整为用户范围内唯一：

- 每个用户最多一份计划；尚未完成首次计划设置的新用户可以没有计划。
- 每个用户每天最多一条体重记录。
- 每个用户每个日期最多一个里程碑。

删除用户时通过数据库事务或级联外键删除该用户的计划、记录和里程碑，保证不会留下孤立数据。

### 数据迁移

迁移按以下顺序执行：

1. 创建 Eason 用户。
2. 将所有现有计划、体重记录和里程碑关联到 Eason，不修改业务字段。
3. 创建 Claire 用户及其 2026-10-01、55.0 kg 至 2026-12-31、45.0 kg 的默认计划。
4. 为 Claire 根据默认计划生成未来里程碑，但不创建实际体重记录。
5. 将 `profile_id` 设为非空，并建立新的用户范围唯一约束与外键。

迁移必须可重复执行而不生成重复用户或重复数据。

## 应用架构与数据流

页面新增当前用户状态 `activeProfileId`。启动时先加载用户列表，再按以下规则选择当前用户：

1. 如果浏览器保存的上次用户仍存在，则恢复该用户。
2. 否则选择 Eason。
3. 如果 Eason 已被重命名或删除，则选择用户列表中的第一人。

选定用户后，所有计划、记录和里程碑查询都必须包含 `profile_id` 条件。所有保存、编辑和删除请求也必须显式携带或校验当前 `profile_id`。没有计划的新用户显示专用空状态，不执行依赖计划日期或体重的图表计算；首次保存计划后再生成里程碑并进入完整看板。

用户切换只改变当前用户 ID 并重新加载该用户数据。上次选择可保存在浏览器中，但业务数据仍以 Supabase 为唯一事实来源。

为了降低串数据风险，用户相关读写封装为明确的方法边界：

- `loadProfiles()`
- `createProfile(name)`
- `renameProfile(profileId, name)`
- `deleteProfile(profileId)`
- `loadProfileData(profileId)`
- 当前计划、记录和里程碑的写操作均要求传入 `profileId`

## 安全与并发

网站继续保持无登录、共享编辑模式，不增加用户鉴权。任何访问者都可以查看和修改所有用户数据，这是本功能的明确产品选择。

数据库仍需启用 RLS，并仅开放本网站实际需要的表操作。服务角色密钥不得出现在前端。用户名唯一性、最后一个用户不可删除、关联数据删除等关键约束必须在数据库侧再次校验，不能只依赖前端。

并发情况下：

- 同名创建或重命名由数据库唯一约束最终拦截。
- 删除已经不存在的用户时返回明确错误，并刷新用户列表。
- 正在查看的用户被其他设备删除时，页面自动切换到剩余用户并显示中文提示。

## 错误处理

- 用户列表加载失败：保留页面当前状态并提示重试。
- 当前用户数据加载失败：不清空原数据，不展示其他用户数据。
- 添加或重命名失败：保留输入内容，显示具体中文错误。
- 删除失败：关闭保存中状态，保留当前用户和页面数据。
- 计划或体重记录保存失败：沿用现有错误反馈，同时确保错误属于当前用户上下文。

## 验收标准

### 数据迁移

- Eason 的线上计划、历史体重和里程碑数量及内容与迁移前一致。
- Claire 的默认计划准确为 2026-10-01 / 55.0 kg 至 2026-12-31 / 45.0 kg。
- Claire 初始没有实际体重记录。

### 用户切换与隔离

- 在 Eason 与 Claire 之间切换时，计划、图表、统计、节点和日志同步切换。
- 给某一用户新增或编辑记录不会改变其他用户的数据。
- 刷新页面后恢复上次选择；如果该用户不存在，则安全回退到有效用户。

### 用户管理

- 可以新增用户并自动切换过去。
- 普通新用户进入无计划空状态，可通过“编辑计划”完成首次设置。
- 可以重命名当前用户，刷新后仍保留。
- 空名称和仅空格名称不能保存。
- 大小写不同的重名不能保存，并显示中文提示。
- 删除用户必须经过二次确认。
- 删除后其关联数据一并删除，其他用户不受影响。
- 最后一个用户不能删除。

### 回归与发布

- 现有日期默认值、未来日期限制、历史补录、计划编辑、节点编辑和图表功能保持有效。
- 桌面端和手机端均可完成用户切换和管理。
- `npm run build:pages` 通过，生成并提交 `docs/`。
- GitHub Pages 发布后在线验证上述交互；验证不新增、覆盖或删除任何真实体重记录。

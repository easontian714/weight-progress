# 减重进度：产品与技术设计

## 目标

创建一个可通过 GitHub Pages 在手机和电脑浏览器中使用的公开减重记录网页。网页不要求登录，所有访问者读取和修改同一份云端数据。产品只服务一轮减重计划，重点呈现总目标、时间与减重进度、每日体重趋势和每周目标节点。

网页名称为「减重进度」，英文小标题为 `WEIGHT JOURNEY`。

## 首期范围

首期包含：

- 编辑本轮计划的开始日期、初始体重、目标日期和目标体重。
- 每个自然日保存一条体重记录；再次保存同一天的数据时覆盖原记录。
- 按计划自动生成每周一节点，并允许编辑尚未结算的节点。
- 自动结算到期节点并冻结其目标、参考体重和结果。
- 展示目标仪表盘、单轨双层进度、实际/计划趋势图、周节点和历史体重记录。
- 所有设备读取和修改同一份公开数据。
- 保存修改历史，以支持误操作后的数据恢复。

首期不包含账户、登录、用户隔离、备注、饮食、运动、体脂、通知、健康平台或文件导入。

## 目标和进度计算

时间进度按开始日期到目标日期之间已经经过的自然日比例计算，并限制在 0% 至 100%。

减重进度按以下公式计算：

```text
(初始体重 - 最新体重) / (初始体重 - 目标体重)
```

显示值限制在 0% 至 100%。当最新体重高于初始体重时仍显示 0%，不设计负进度状态。

首页使用一条双层进度轨道：

- 底层从起点延伸到时间进度，使用暖色。
- 上层从起点延伸到减重进度，使用绿色。
- 落后时，绿色之后露出的暖色区间表示落后幅度。
- 达标时，两层完全重合，只显示绿色。
- 领先时，绿色覆盖暖色并继续向前，只显示绿色。

文字同时标明实际进度、时间进度，以及当前相对计划体重领先或落后的千克数。

### 编辑和重新规划

- 用户可以编辑尚未结算节点的目标体重。
- 修改总目标后，仅重新生成当前日期之后的未结算节点。
- 当前日期上的节点视为已进入结算范围，不被重新生成。
- 已结算节点在数据库中保存当时的目标体重、参考记录日期、参考体重、结果和结算时间，后续修改总目标不会改变历史结果。

### 自动结算

- 周一节点优先使用该周一当天的体重记录结算。
- 如果当天尚未记录，节点显示「等待今日打卡」。
- 当当天记录创建或修改后，节点自动结算或重新结算；当天结束后结果冻结。
- 实际体重小于或等于节点目标时为「已完成」，否则为「未完成」。
- 最终目标节点使用相同规则。

## 体重记录

- 新增表单默认选择今天，只输入日期和体重。
- 体重单位固定为 kg，输入和显示保留一位小数。
- 数据库以日期作为唯一键；保存已有日期时执行更新而不是新增重复记录。
- 历史列表按日期倒序排列，展示与上一条记录相比的变化。
- 编辑沿用相同表单；删除必须二次确认。

## 趋势图

趋势图始终覆盖本轮计划的完整时间范围，并同时绘制：

- 实际体重折线：使用全部每日记录。
- 计划目标线：按总目标线性插值；手动修改的周节点以节点值为准，节点之间线性连接。

为了避免小屏幕过密：

- 手机端最多显示约 20 个实际数据圆点和 5 个横轴日期标签。
- 电脑端最多显示约 40 个实际数据圆点和 8 个横轴日期标签。
- 折线本身始终使用全部记录，只对圆点和轴标签进行等间隔抽样。
- 首条、最新一条、最高点和最低点必须显示圆点。
- 点击、触摸或键盘聚焦数据位置时显示准确日期和体重。

## 数据架构

前端为原生 HTML、CSS 和 JavaScript，通过 GitHub Pages 静态托管。云端使用 Supabase。

建议表结构：

- `weight_plan`：唯一计划记录，保存起止日期和起止体重。
- `weight_entries`：每日体重，`entry_date` 唯一。
- `weight_milestones`：周节点、是否手动调整及冻结后的结算快照。
- `weight_audit_log`：每次新增、修改或删除前后的 JSON 快照、操作时间和随机客户端标识。

由于产品明确允许任何访问者修改，匿名角色具有这些表所需的读取和写入权限。数据库只暴露本项目所需字段；前端不包含服务角色密钥。公开的 Supabase publishable key 仅配合受限的行级策略使用。

## 数据流与并发

页面加载时并行读取计划、体重和节点。写入成功后重新读取受影响的数据，而不是只相信本地状态。

写入采用数据库唯一约束和原子函数：

- 同日体重写入使用 upsert，最后一次成功提交为准。
- 修改计划与重算未来节点在一个数据库事务中完成。
- 删除和更新先写审计快照，再执行变更。
- 每条主要记录保存 `updated_at`；当提交基于过期版本时，提示数据已被其他设备更新并刷新页面，避免静默覆盖。

## 错误与恢复

- 网络读取失败时显示可重试错误状态，不展示虚假的空数据。
- 写入期间禁用重复提交；失败后保留用户输入并允许重试。
- 删除操作需要确认。
- 审计日志至少保留最近 100 次修改；恢复功能首期可通过受保护的数据库操作执行，不必暴露在日常界面。

## 可访问性与响应式

- 所有按钮、表单和图表数据点可通过键盘操作。
- 不只依靠颜色表达完成、未完成和领先、落后状态。
- 移动端触控目标不小于 44 px。
- 体重输入使用适合小数的数字键盘。
- 支持窄至 320 px 的手机视口和常见桌面宽度。

## 验证

实现后至少验证：

- 目标进度和时间进度边界值。
- 跨月份、跨年份和夏令时环境下的日期计算。
- 每周一及最终节点的线性插值和一位小数显示。
- 修改计划只影响未来节点。
- 当天记录触发节点结算，历史节点不被后续修改改变。
- 同一天重复保存不会生成两条记录。
- 20/40 圆点和 5/8 日期标签的抽样规则保留关键点。
- 手机和电脑布局、触控、键盘和加载/失败状态。
- Supabase 匿名权限无法访问未声明的数据或执行项目范围外操作。
